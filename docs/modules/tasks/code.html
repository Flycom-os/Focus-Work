💻 Разбор кода модуля Задач

В этом разделе мы заглянем "под капот" нашего таск-трекера. Разберем ключевые файлы, реализующие доску, серверные действия и оптимистичное обновление состояния кэша в браузере.

⚡ 1. Серверные экшены (Actions)

Серверные экшены в Next.js — это функции, которые выполняются строго на сервере, но могут вызываться напрямую из клиентских компонентов как обычные асинхронные JS-функции.

Файл src/app/actions/tasks.ts содержит CRUD операции с задачами.

"use server";

import { prisma } from "@/lib/prisma";
import { revalidatePath } from "next/cache";
import { getServerSession } from "next-auth";
import { authOptions } from "@/lib/auth";

export async function moveTaskAction(
  taskId: string,
  targetColumnId: string,
  newPosition: number
) {
  // 1. Проверяем авторизацию пользователя
  const session = await getServerSession(authOptions);
  if (!session || !session.user) {
    throw new Error("Не авторизован");
  }

  // 2. Получаем задачу, чтобы проверить доступ к проекту
  const task = await prisma.task.findUnique({
    where: { id: taskId },
    select: { projectId: true }
  });

  if (!task) {
    throw new Error("Задача не найдена");
  }

  // 3. Проверяем, состоит ли пользователь в этом проекте (безопасность!)
  const userProject = await prisma.projectMember.findFirst({
    where: {
      projectId: task.projectId,
      userId: session.user.id
    }
  });

  if (!userProject) {
    throw new Error("У вас нет доступа к этому проекту");
  }

  // 4. Обновляем статус и позицию задачи
  const updatedTask = await prisma.task.update({
    where: { id: taskId },
    data: {
      statusId: targetColumnId,
      position: newPosition
    }
  });

  // 5. Очищаем кэш Next.js для этого проекта, чтобы обновились SSR-страницы
  revalidatePath(`/projects/${task.projectId}/board`);

  return { success: true, task: updatedTask };
}

🕵️‍♂️ Поблочное объяснение логики:

  • Строка 1: "use server"; — Директива говорит сборщику Webpack/Turbopack, что этот файл содержит исключительно серверные методы. Клиентский бандл не получит этот код, а значит наши пароли и прямой доступ к БД в безопасности.
  • Шаги 1-3 (Безопасность): Мы никогда не доверяем клиенту на слово. Даже если клиент передал правильный `taskId`, мы проверяем через сессию пользователя (`getServerSession`), имеет ли он юридическое право изменять данные в рамках этого проекта. Это защищает нас от IDOR-уязвимостей.
  • Шаг 4 (Prisma update): Мы обновляем только две переменные: `statusId` (новая колонка) и `position` (float позиция для сортировки).
  • Шаг 5 (Сброс SSR кэша): Вызов `revalidatePath` указывает Next.js сбросить кэшированный рендеринг страницы Kanban-доски. При следующем обновлении страницы пользователь получит актуальную верстку прямо от сервера.

📋 2. Клиентский компонент KanbanBoard.tsx

Для реализации перетаскивания (Drag and Drop) используется библиотека @hello-pangea/dnd (современный форк устаревшей react-beautiful-dnd, полностью поддерживающий React 18). 

"use client";

import React from "react";
import { DragDropContext, Droppable, Draggable, DropResult } from "@hello-pangea/dnd";
import { useTasksMutation } from "@/hooks/useTasks";

interface Task {
  id: string;
  title: string;
  position: number;
}

interface Column {
  id: string;
  name: string;
  tasks: Task[];
}

export default function KanbanBoard({ initialColumns }: { initialColumns: Column[] }) {
  const [columns, setColumns] = React.useState(initialColumns);
  const { mutateMoveTask } = useTasksMutation();

  const onDragEnd = (result: DropResult) => {
    const { destination, source, draggableId } = result;

    // Если перетащили "в никуда" - ничего не делаем
    if (!destination) return;

    // Если перетащили в ту же точку - ничего не делаем
    if (
      destination.droppableId === source.droppableId &&
      destination.index === source.index
    ) return;

    const sourceCol = columns.find(col => col.id === source.droppableId);
    const destCol = columns.find(col => col.id === destination.droppableId);

    if (!sourceCol || !destCol) return;

    // Локально пересчитываем новую позицию (Float)
    let newPosition = 0;
    const destTasks = [...destCol.tasks];
    
    // Если перетаскиваем внутри одной колонки
    if (source.droppableId === destination.droppableId) {
      destTasks.splice(source.index, 1);
    }

    if (destination.index === 0) {
      // Ставим в самое начало
      newPosition = destTasks.length > 0 ? destTasks[0].position / 2 : 1000;
    } else if (destination.index >= destTasks.length) {
      // Ставим в самый конец
      newPosition = destTasks.length > 0 ? destTasks[destTasks.length - 1].position + 1000 : 1000;
    } else {
      // Вставляем между двумя задачами
      const prevPos = destTasks[destination.index - 1].position;
      const nextPos = destTasks[destination.index].position;
      newPosition = (prevPos + nextPos) / 2;
    }

    // Вызываем хук-мутацию для отправки на бэк и обновления кэша
    mutateMoveTask({
      taskId: draggableId,
      targetColumnId: destination.droppableId,
      newPosition: newPosition
    });
  };

  return (
    <DragDropContext onDragEnd={onDragEnd}>
      <div class="flex gap-4 p-4 overflow-x-auto select-none">
        {columns.map(col => (
          <div key={col.id} class="w-72 bg-slate-100 dark:bg-slate-900 rounded-lg p-3 shrink-0">
            <h3 class="font-bold mb-3 text-slate-700 dark:text-slate-300">{col.name}</h3>
            
            <Droppable droppableId={col.id}>
              {(provided) => (
                <div
                  {...provided.droppableId}
                  ref={provided.innerRef}
                  class="space-y-2 min-h-[500px]"
                >
                  {col.tasks.map((task, index) => (
                    <Draggable key={task.id} draggableId={task.id} index={index}>
                      {(provided, snapshot) => (
                        <div
                          ref={provided.innerRef}
                          {...provided.draggableProps}
                          {...provided.dragHandleProps}
                          class={`p-4 rounded bg-white dark:bg-slate-800 shadow-sm border border-slate-200 dark:border-slate-700 ${
                            snapshot.isDragging ? 'rotate-2 shadow-lg scale-102 border-indigo-500' : ''
                          }`}
                        >
                          <h4 class="font-semibold text-sm">{task.title}</h4>
                        </div>
                      )}
                    </Draggable>
                  ))}
                  {provided.placeholder}
                </div>
              )}
            </Droppable>
          </div>
        ))}
      </div>
    </DragDropContext>
  );
}

🔄 3. Хук useTasks.ts и Optimistic Updates

Чтобы UI доски реагировал мгновенно без раздражающего спиннера, мы пишем кастомную мутацию с помощью @tanstack/react-query. 

import { useMutation, useQueryClient } from "@tanstack/react-query";
import { moveTaskAction } from "@/app/actions/tasks";

interface MoveTaskVariables {
  taskId: string;
  targetColumnId: string;
  newPosition: number;
}

export function useTasksMutation() {
  const queryClient = useQueryClient();

  const { mutate: mutateMoveTask } = useMutation({
    mutationFn: async ({ taskId, targetColumnId, newPosition }: MoveTaskVariables) => {
      // Вызываем наш Server Action напрямую
      return moveTaskAction(taskId, targetColumnId, newPosition);
    },
    
    // Шаг 1. Перед отправкой запроса на сервер
    onMutate: async (variables) => {
      // Отменяем все исходящие перезапросы доски, чтобы они не затерли оптимистичный кэш
      await queryClient.cancelQueries({ queryKey: ["board-data"] });

      // Делаем снимок текущего состояния кэша (Snapshot)
      const previousBoard = queryClient.getQueryData(["board-data"]);

      // Оптимистично перезаписываем кэш новыми координатами
      queryClient.setQueryData(["board-data"], (oldData: any) => {
        if (!oldData) return oldData;
        
        // Клонируем данные доски
        const updatedColumns = oldData.columns.map((col: any) => {
          // Удаляем задачу из старой колонки
          const tasks = col.tasks.filter((t: any) => t.id !== variables.taskId);
          return { ...col, tasks };
        });

        // Находим задачу, которую перенесли
        let movedTask: any = null;
        for (const col of oldData.columns) {
          const found = col.tasks.find((t: any) => t.id === variables.taskId);
          if (found) {
            movedTask = { ...found, statusId: variables.targetColumnId, position: variables.newPosition };
            break;
          }
        }

        // Добавляем задачу в целевую колонку
        if (movedTask) {
          const targetCol = updatedColumns.find((col: any) => col.id === variables.targetColumnId);
          if (targetCol) {
            targetCol.tasks.push(movedTask);
            // Сортируем задачи по новой позиции
            targetCol.tasks.sort((a: any, b: any) => a.position - b.position);
          }
        }

        return { ...oldData, columns: updatedColumns };
      });

      // Возвращаем снимок для возможности отката в случае ошибки
      return { previousBoard };
    },

    // Шаг 2. Если сервер ответил ошибкой
    onError: (err, variables, context: any) => {
      console.error("Dnd error, rolling back cache:", err);
      // Возвращаем данные из сохраненного снимка
      if (context?.previousBoard) {
        queryClient.setQueryData(["board-data"], context.previousBoard);
      }
    },

    // Шаг 3. Всегда (успех или ошибка)
    onSettled: () => {
      // Инвалидируем кэш, чтобы гарантировать 100% консистентность с БД
      queryClient.invalidateQueries({ queryKey: ["board-data"] });
    }
  });

  return { mutateMoveTask };
}
🚀 Зачем это нужно? Пользователю кажется, что приложение работает локально на скорости 120 FPS. Перетаскивание происходит за 0 мс. Даже если интернет работает с перебоями или пинг до сервера составляет 300 мс, интерфейс не зависает.
