🛠 Фичи и Практические гайды

В этом документе описан функционал модуля задач и предоставлены пошаговые инструкции для расширения возможностей таск-трекера.

📌 1. Основные фичи модуля

Наш таск-менеджер реализует классический подход Agile и Scrum. Ниже описан ключевой функционал, с которым вы столкнетесь при доработке системы:

⏱ Списание времени (Time Tracking)

Каждая задача имеет поля estimation (оценка времени в минутах) и timeSpent (уже залогированное время). Для учета пишется отдельная таблица TimeLog, фиксирующая автора, затраченное время и текстовый комментарий к списанию (например, «фикс бага с версткой»).

📅 Спринты (Sprints)

Задачи могут объединяться в спринты. Спринт имеет даты начала, окончания и признак активности. Если задача переносится в новый спринт из незаконченного старого, ей присваивается статус переноса (carry-over), что важно для построения точных графиков эффективности команды (Burndown Charts).

🔗 Подзадачи (Subtasks)

Связь задач вида «один ко многим» со ссылкой на саму себя (parentId). При закрытии всех подзадач, система автоматически предлагает перевести родительскую задачу в статус «Завершено» с помощью триггеров Prisma.

🏷 Теги и Фильтрация

Задачи маркируются тегами. Чтобы фильтровать доску без перерендеринга сотен карточек, мы храним состояние фильтров в URL-строке браузера (через query-параметры Next.js). Это позволяет делиться ссылкой на предфильтрованную доску.

🚀 2. Практические руководства (How-To)

🛠 Гайд 1: Как добавить новый статус/колонку в доску задач?

Предположим, вам нужно добавить новый системный статус "На тестировании" (QA), который должен автоматически появляться на всех создаваемых досках проектов.

Шаг 1: Добавление системного дефолта в Prisma Seed

Откройте файл prisma/seed.ts. Добавьте новую колонку в массив инициализации доски:

const defaultColumns = [
  { name: "Бэклог", position: 1000 },
  { name: "В работе", position: 2000 },
  { name: "На тестировании", position: 3000 }, // <-- Наш новый статус
  { name: "Выполнено", position: 4000 }
];

Шаг 2: Обновление типов во фронтенде

Убедитесь, что типы колонок в types/index.ts соответствуют Prisma-схеме. Запустите генерацию типов Prisma:

npx prisma generate

Шаг 3: Адаптация UI-компонента

В компоненте KanbanBoard.tsx убедитесь, что цвет границы или шапка колонки стилизуются в соответствии со статусом. Можно добавить кастомный бейдж:

// Выделяем колонку тестирования особым фиолетовым цветом
const getHeaderColor = (name: string) => {
  if (name === "На тестировании") return "border-t-4 border-purple-500";
  if (name === "В работе") return "border-t-4 border-blue-500";
  if (name === "Выполнено") return "border-t-4 border-emerald-500";
  return "border-t-4 border-slate-300";
};

🛠 Гайд 2: Как привязать Задачу к Клиенту из модуля CRM (Кросс-модульная связь)?

Бизнес-требование: менеджер в CRM должен иметь возможность поставить разработчикам задачу со ссылкой на карточку конкретного клиента.

Шаг 1: Расширение схемы БД

Свяжем модель Task с моделью Customer из CRM. Связь должна быть необязательной (nullable), чтобы обычные задачи могли существовать без клиента.

model Task {
  id          String    @id @default(uuid())
  title       String
  // ... все остальные существующие поля ...
  
  // Новая кросс-модульная связь
  customerId  String?
  customer    Customer? @relation(fields: [customerId], references: [id], onDelete: SetNull)
}

// В модель Customer (CRM) добавляем обратную связь:
model Customer {
  id          String   @id @default(uuid())
  name        String
  // ... существующие поля ...
  tasks       Task[]
}

Шаг 2: Накатывание миграции

Запустите миграцию в терминале, назвав ее соответствующим образом:

npx prisma migrate dev --name link_tasks_to_customers
⚠️ Внимание при миграции: Так как мы использовали onDelete: SetNull и поле является nullable (customerId String?), миграция применится безболезненно даже на работающей базе с заполненными задачами. Будьте осторожны, не делайте поле обязательным, иначе миграция упадет при попытке заполнить старые записи!

Шаг 3: Передача данных в Server Action создания задачи

Добавьте параметр в метод создания задачи в файле src/app/actions/tasks.ts:

export async function createTaskAction(data: {
  title: string;
  projectId: string;
  columnId: string;
  customerId?: string; // <-- Новый параметр
}) {
  const session = await getServerSession(authOptions);
  if (!session) throw new Error("Не авторизован");

  return prisma.task.create({
    data: {
      title: data.title,
      projectId: data.projectId,
      statusId: data.columnId,
      customerId: data.customerId || null,
      creatorId: session.user.id,
      position: 1000 // Начальная дефолтная позиция
    }
  });
}

❓ 3. FAQ и Частые ошибки разработчиков

Это классическая ошибка в библиотеке Drag & Drop, когда идентификаторы элементов пересекаются. Например, вы случайно создали две задачи с пустым ID или присвоили ID колонки в качестве ID задачи.

Решение: Убедитесь, что в схеме БД поле `id` генерирует уникальный UUID, а во фронтенде в качестве ключей `key={task.id}` и `draggableId={task.id}` передается именно уникальный UUID из базы, а не индекс массива `index`.

Если интернет медленный, сетевой запрос к Server Action выполняется долго (например, 2-3 секунды). Если в этот момент пользователь попытается перетащить другую карточку, кэш React Query начнет конфликтовать со старым запросом.

Решение: Мы предусмотрели отмену активных перезапросов при драге: await queryClient.cancelQueries({ queryKey: ["board-data"] }); внутри метода onMutate. Проверьте, что вы передаете верный `queryKey` и не удалили эту строчку.
