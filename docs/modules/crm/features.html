🛠 Фичи и Практические гайды CRM

В данном разделе детально расписана интеграция CRM с внешними системами учета (1С) и приведены инструкции для администрирования видеонаблюдения и воронки.

📌 1. Бизнес-фичи модуля CRM

CRM-система автоматизирует продажи и снабжение. Ниже описан внутренний функционал и интеграции:

📊 Финансовая аналитика (Recharts)

На главном дашборде CRM выводятся графики прибыли, среднего чека и конверсий. Данные агрегируются на сервере с помощью Prisma SQL-запросов (группировка по месяцам и дням) и передаются на клиент, где отрисовываются через SVG-библиотеку recharts.

📦 Складской учет остатков (Stock)

При создании успешной сделки система автоматически проверяет наличие продуктов на складе. Если товара достаточно, списывается соответствующее количество из модели Stock. Если товара не хватает, сделка блокируется, а менеджеру выводится предупреждение.

🏢 Двусторонняя интеграция с 1С

Для синхронизации каталога товаров и оплат используется фоновая gRPC-служба. Раз в час 1С выгружает остатки товаров на наш склад, а CRM отправляет обратно данные о проведенных оплатах по сделкам.

🛡 Детекция лиц на складах (Face Recognition)

Видеокамеры подключены к ML-сервису детекции лиц. При появлении человека в кадре на складе в нерабочее время, система распознает лицо сотрудника. Если это посторонний, CRM мгновенно рассылает алерты в Telegram руководству.

📐 2. Надежная интеграция с 1С (Transactional Outbox Pattern)

При отправке данных из CRM в 1С (например, информации о новой оплате) может случиться сбой: в 1С пропал свет, зависла сеть или бэкенд 1С перезапускается.

Если мы сделаем запрос к 1С прямо внутри HTTP-запроса пользователя, то в случае ошибки 1С транзакция в нашей БД откатится, а менеджер получит ошибку 500. Это плохой UX.

Решение: Transactional Outbox Pattern

Вместо отправки запроса в 1С напрямую, мы создаем запись об оплате в таблице Transaction и ОДНОВРЕМЕННО в рамках одной транзакции БД записываем задачу отправки в таблицу OutboxEvent: 

model OutboxEvent {
  id        String   @id @default(uuid())
  type      String   // Например: "TRANSACTION_CREATED"
  payload   Json     // Данные транзакции
  status    String   // PENDING, PROCESSED, FAILED
  attempts  Int      @default(0)
  createdAt DateTime @default(now())
}

Отдельный фоновый воркер (Cron-задача) раз в 10 секунд считывает из БД события со статусом `PENDING`, пытается отправить их в 1С. В случае успеха статус меняется на `PROCESSED`. Если 1С лежит, воркер повторит попытку через минуту (используя алгоритм Exponential Backoff).

🚀 3. Практические руководства (How-To)

🛠 Гайд: Как добавить новый этап "В сборке" (ASSEMBLY) в воронку сделок?

Бизнес запросил добавить новый статус сборки товара на складе перед тем, как выставить счет на оплату.

Шаг 1: Обновление Prisma схемы

Добавьте значение ASSEMBLY в перечисление DealStage:

enum DealStage {
  LEAD
  NEGOTIATION
  ASSEMBLY      // <-- Наш новый этап воронки
  CONTRACT
  PAYMENT
  COMPLETED
  LOST
}

Шаг 2: Создание миграции БД

npx prisma migrate dev --name add_assembly_stage_to_deals

Шаг 3: Добавление этапа на фронтенд

Откройте файл src/components/crm/DealPipeline.tsx и добавьте новый этап в массив отображения колонок воронки:

const STAGES = [
  { id: "LEAD", name: "Новые лиды" },
  { id: "NEGOTIATION", name: "Переговоры" },
  { id: "ASSEMBLY", name: "Сборка заказа" }, // <-- Добавили на доску!
  { id: "CONTRACT", name: "Согласование договора" },
  { id: "PAYMENT", name: "Ожидание оплаты" },
  { id: "COMPLETED", name: "Сделка закрыта" }
];

🛠 Гайд: Как подключить новую IP-камеру склада в CRM?

Шаг 1: Получение RTSP ссылки

Узнайте RTSP ссылку на поток камеры у системного администратора. Пример: rtsp://admin:secret@192.168.10.45:554/h264Preview_01_main.

Шаг 2: Добавление записи в БД

Добавьте запись о камере в PostgreSQL, связав ее с нужным ID склада (warehouseId):

await prisma.camera.create({
  data: {
    name: "Камера Склад Восток №1",
    rtspUrl: "rtsp://admin:secret@192.168.10.45:554/h264Preview_01_main",
    warehouseId: "some-warehouse-uuid-here"
  }
});

Шаг 3: Запуск транскодирования на сервере

Наш серверный бэкенд транскодирования автоматически считывает записи камер из БД и запускает для каждой из них отдельный фоновый процесс FFmpeg:

// Фоновый запуск FFmpeg для новой камеры
const startTranscoding = (camera: Camera) => {
  const ffmpegCmd = `ffmpeg -i ${camera.rtspUrl} -codec:v libx264 -preset superfast -codec:a aac -f hls -hls_time 2 -hls_list_size 5 -hls_flags delete_segments /tmp/streams/${camera.id}/stream.m3u8`;
  exec(ffmpegCmd);
};

❓ 4. FAQ: Устранение неполадок видеонаблюдения

Это происходит, если клиентский плеер Hls.js не может прочитать файл-манифест stream.m3u8.

Причины и диагностика:

  1. Камера отключена физически или поменялся ее IP-адрес. В этом случае процесс FFmpeg на сервере падает с ошибкой тайм-аута. Проверьте пинг до камеры из консоли сервера.
  2. Кончилось свободное место во временной папке /tmp на сервере. Очистите кэш сегментов.
  3. Падение фонового процесса Node.js транскодера. Перезапустите службу: pm2 restart ffmpeg-transcoder.
