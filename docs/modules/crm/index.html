💼 Модуль CRM (Бизнес-центр)

Модуль CRM объединяет управление взаимоотношениями с клиентами, воронки сделок, складской учет остатков и систему видеонаблюдения за физическими складами и офисами в единый рабочий дашборд.

🌟 1. Введение и бизнес-логика

Если Модуль Задач — это инструмент для разработчиков, то CRM — это главный орган управления бизнесом для менеджеров по продажам, кладовщиков и руководителей.

CRM решает три ключевые задачи:

  • Продажи: Ведение сделок по этапам воронки (Лид ➡️ Переговоры ➡️ Договор ➡️ Оплата ➡️ Выполнено).
  • Склады (Inventory): Партионный учет товаров. Мы должны точно знать, на каком складе лежит конкретный товар, какова его себестоимость и сколько штук зарезервировано под сделки.
  • Контроль и безопасность (Камеры): Интеграция IP-видеокамер. Менеджер может прямо из CRM открыть камеру на складе №2 и проверить, идет ли отгрузка товара клиенту, не выходя из кабинета.
💡 Аналогия для джунов: Представьте, что CRM — это ресторан. Клиенты делают заказы (Сделки). Официанты смотрят на кухню через стекло (Видеокамеры), а продукты лежат на полках холодильников (Склады). Бухгалтерия записывает каждую копейку в кассовую книгу (Транзакции), из которой нельзя вырывать листы.

📹 2. Стриминг видеокамер (RTSP to HLS Data Flow)

Большинство IP-видеокамер выдают видеопоток по протоколу RTSP (Real-Time Streaming Protocol). Современные браузеры (Chrome, Firefox, Safari) нативно RTSP проигрывать не умеют.

Чтобы показать поток в веб-интерфейсе, мы транскодируем его на лету в формат HLS (HTTP Live Streaming) с помощью утилиты FFmpeg на сервере:

graph TD Camera[📹 IP Камера] -- RTSP Stream (H.264 / AAC) --> FFmpeg[⚙️ FFmpeg Transcoder] FFmpeg -- Нарезка потока на .ts сегменты --> Disk[(📂 Временная папка в ОЗУ /tmp)] FFmpeg -- Создание плейлиста .m3u8 --> Disk Disk -- Чтение по HTTP (Next.js API Route) --> Express[🚀 API Сервер] Express -- Раздача статических сегментов --> Player[💻 Клиент (Hls.js Player)] classDef default fill:#f9f9f9,stroke:#333,stroke-width:1px; classDef cam fill:#eef2ff,stroke:#6366f1,stroke-width:2px; classDef trans fill:#fdf2f8,stroke:#ec4899,stroke-width:2px; classDef play fill:#ecfdf5,stroke:#10b981,stroke-width:2px; class Camera cam; class FFmpeg,Express trans; class Player play;

FFmpeg непрерывно запрашивает кадры у камеры, упаковывает их в мелкие 2-секундные файлы с расширением `.ts` и записывает их во временную папку в оперативной памяти (чтобы поберечь ресурс SSD-диска). Также создается файл-индекс `.m3u8` (плейлист). Клиентский плеер Hls.js постоянно скачивает этот плейлист и воспроизводит `.ts` файлы один за другим, давая задержку трансляции всего около 3-4 секунд.

🗄 3. Prisma-модели и Финансовая Неизменяемость

Схема БД для CRM включает в себя справочники клиентов, сделок, продуктов и камер. Обратите внимание на модель Transaction: финансы требуют строгого аудита. 

model Customer {
  id        String   @id @default(uuid())
  name      String
  email     String?  @unique
  phone     String?
  deals     Deal[]
  transactions Transaction[]
  createdAt DateTime @default(now())
}

model Deal {
  id          String      @id @default(uuid())
  title       String
  amount      Float       // Сумма сделки
  stage       DealStage   @default(LEAD)
  customerId  String
  customer    Customer    @relation(fields: [customerId], references: [id])
  transactions Transaction[]
  createdAt   DateTime    @default(now())
  updatedAt   DateTime    @updatedAt
}

model Warehouse {
  id        String   @id @default(uuid())
  name      String
  address   String?
  stocks    Stock[]
  cameras   Camera[]
}

model Product {
  id        String   @id @default(uuid())
  sku       String   @unique // Артикул
  name      String
  price     Float
  stocks    Stock[]
}

model Stock {
  id          String    @id @default(uuid())
  warehouseId String
  warehouse   Warehouse @relation(fields: [warehouseId], references: [id], onDelete: Cascade)
  productId   String
  product     Product   @relation(fields: [productId], references: [id], onDelete: Cascade)
  quantity    Int       @default(0) // Количество на конкретном складе
}

model Camera {
  id          String    @id @default(uuid())
  name        String
  rtspUrl     String    // Ссылка на RTSP поток камеры
  warehouseId String
  warehouse   Warehouse @relation(fields: [warehouseId], references: [id])
}

model Transaction {
  id          String   @id @default(uuid())
  amount      Float    // Положительное (приход) или отрицательное (расход)
  description String
  dealId      String?
  deal        Deal?    @relation(fields: [dealId], references: [id])
  customerId  String
  customer    Customer @relation(fields: [customerId], references: [id])
  createdAt   DateTime @default(now()) // Изменять эту запись после создания НЕЛЬЗЯ
}

enum DealStage {
  LEAD
  NEGOTIATION
  CONTRACT
  PAYMENT
  COMPLETED
  LOST
}

🛡 Важное правило: Неизменяемость финансовых транзакций (Ledger Pattern)

В базе данных CRM модель Transaction спроектирована так, что записи в нее можно только вставлять (Insert). В кодовой базе наложен строгий запрет на операции `update` и `delete` для этой таблицы.

Почему это критично:

Если менеджер ошибся и случайно зачислил клиенту 10 000 рублей вместо 1000, правильное исправление в бухгалтерии — это не редактирование старой строки, а создание новой корректирующей транзакции с суммой -9000 рублей.

Это гарантирует полную прозрачность аудита. Любая попытка изменить исторические данные в таблице транзакций расценивается системой безопасности как финансовое мошенничество.
